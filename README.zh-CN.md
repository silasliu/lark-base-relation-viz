# 任务依赖图（多维表格扩展程序）

只读展示多维表格里的任务依赖关系与父子关系，用 AntV G6 绘制。

English: [README.md](README.md)

## 它做什么

- **视图切换** — 层级·上下（默认）/ 层级·左右 / 力导向 / 环形 / 辐射。
- **节点** — 标题、截止时间（逾期标红）、关系徽标（未完成显示 **`阻塞：N`**，已完成显示 **`解锁：N`**——同一个数字，两种含义）、**所属清单**（蓝色胶囊）+ 标签胶囊（最多 2 个 + `+N`）；左侧色条 红=未完成 / 灰绿=已完成。
- **依赖边** — **任务 → 前置**，箭头指向所等待的那件事。布局上**前置在上、任务在下**，锚点按两节点实际相对位置动态选取。三态着色：红=前置未完成（阻塞中）、绿=前置已完成（可推进）、灰=本任务已完成（关系已失效）。
- **同时显示多种关系** — 在「更多 → 同时显示」里勾选多个关联字段。**颜色只表示状态**，关系种类用**线型 + 箭头形状 + 线宽**区分（实线实心三角 / 虚线空心箭头 / 点线菱形）。图例只列出当前图里真实出现的关系。
- **父子边** — 父 → 子，灰色虚线，无箭头。**可在设置里关闭**；关掉后只有父子关系的任务不再出现在图里。
- **清单** — 可动手 / 被阻塞 / 已完成 / 全部，支持搜索清单与标签。**点条目只在图里定位，不会跳到详情页**，可以连着看好几条不用来回切标签。
- **详情** — 任务内容（描述正文）、可点击的前置/后继/父/子任务、可点击的清单与标签（点击即筛选）、网页链接与客户端链接。
- **交互** — 单击选中并高亮邻接（其余压到 45%，仍看得清）、双击节点唤起滴答、右键折叠/展开、滚轮按物理距离缩放、**双击空白处收起侧栏**。
- **框选** — 按住 **Shift** 在空白处拖动框选多个节点，之后拖任意一个就能整组移动。用 Shift 是为了不抢掉「拖动空白处平移画布」。
- **显示全部 vs 整理** — `显示全部` 只把当前图适配进视口，不动布局；`整理` 会**展开所有折叠**、重新布局、消除重叠，再适配全图，是「把这张图恢复整齐」的按钮。
- **导出** — 两种：**导出全图**（整张图，不受视口限制）、**导出当前视图**（只截现在看得到的部分）。都是白底 PNG，最长边上限 4096px，超出等比压缩，文件名带日期时间。
- **全屏** — 只把插件自己的可用区域铺满（隐藏工具栏与侧栏，`Esc` 退出），**不打开新窗口或标签页**，也不依赖浏览器 Fullscreen API（飞书 iframe 可能拒绝）。
- **侧栏** — 可收起；窄屏（飞书侧边栏）下移到底部，收起时是一行横向入口，展开时占下半部分，不覆盖画布。

## 哪些记录会出现在图里，「已完成」怎么算

只有**未完成**的记录会作为种子。未完成与否由你指定的状态字段决定：

- **更多 → 完成状态** 里列出表里所有单选 / 多选字段
- 选中一个，再勾选哪些选项算**已完成**（选项 id 与名称都参与匹配，改名字也不会漏判）
- 一条记录只要命中任一勾选选项就算已完成
- 选「不用状态（中性）」则完全不做判断

第一次使用时，插件会自动挑一个名字像 `状态 / status / stage` 的字段，并按选项名预勾
（`已完成`、`Done` 这类；`未完成`、`开始` 这类会跳过）。你改一次就记住了。

### 中性模式（没有状态字段）

没有状态字段时，插件**不会**假装所有关系都被阻塞：

| | 有状态 | 中性 |
|---|---|---|
| 依赖边颜色 | 红 / 绿 / 灰 | **浅蓝** `#a8c0f5` |
| `阻塞 / 解锁` 徽标 | 显示 | 不显示 |
| 清单分栏 | 可动手 / 被阻塞 / 已完成 / 全部 | **只有「全部」** |
| 图例 | 三态 | 多一条「状态未知」 |

这一点很关键：以前没有状态列的表会把每条边画成红色，看起来像「你被卡住了」，
而事实只是「我不知道」。

## 读取大表（超过 200 条）

`getRecordsByPage` 单次最多返回 200 条，更大的表靠分页读完。分页令牌是 SDK 的 `PageToken`，
类型是**数字**——把它转成字符串再回传，宿主会在第二页直接报
`table operation parameter exception error`。`0` 是合法令牌，不会被当成「没有下一页」。
读取过程中工具栏显示 `已读 N / M 条`。三种保护避免死循环：令牌重复、`hasMore` 却没有令牌、页数上限。

## 窄容器（飞书侧边栏）下的行为

| 画布宽度 | 节点尺寸 | 侧栏 |
|---|---|---|
| ≥ 560px | 常规（宽 132–240） | 常驻右侧，可收起 |
| < 560px | **紧凑**（宽 100–168，更小留白） | 移到底部，收起为一行入口 |

缩放有**两个**下限，刻意分开：

| 动作 | 下限 | 原因 |
|---|---|---|
| 滚轮 / ＋－ 按钮 | `0.2` | 再小就彻底不知道自己看的是哪一块 |
| 显示全部 / 整理（自动适配） | `0.02` | 大图必须允许比手动下限更小，否则永远差一块 |

缩到很低时文字不可读，但能看清整体结构，状态栏显示「整体视图」而不是误导性的「最小缩放」。
自动适配不会把小图放大超过 100%。用户没手动缩放过时，容器尺寸变化会重新适配，
所以「第一次适配发生在布局还没定型时」不会留下被裁掉的图。

## 交付给别人使用

### 1. 注册插件应用（一次性）

1. 打开 [飞书开发者后台](https://open.feishu.cn/app)，创建**企业自建应用**。
2. 添加应用能力 → **多维表格插件** → 数据表视图。
3. 把分配的 `blockTypeID` 填进 `block.json`。

### 2. 读的是哪张表

插件打开的是**你在 Base 界面里正看着的那张表**（URL 里的 `?table=`）。
回退顺序：正在看的表 → 上次的选择 → 第一张。

多表 Base 里这点很关键：以前盲选「第一张表」，如果那张表没有自关联字段，
表现就和「插件打不开」一模一样。

### 3. 配置字段

插件**不写死字段名**：打开后列出当前表的所有自关联字段，由你选择。

字段方向默认按「字段里存的是我的前置」处理。如果某张表的单向关联方向相反（字段存的是「我的后续」），
箭头会整体反掉；这种情况下把 `config` 语义调整为 `fieldIsSuccessor` 即可。

选择会**持久化**到飞书 Bridge（同一文档的同一插件共享），下次打开直接还原。

### 4. 部署（把页面地址填进飞书）

飞书扩展脚本的官方用法是**自己提供一个页面地址**：在多维表格里「新增脚本」粘贴 URL。
没有「上传后由飞书托管」的 CLI（`block-basekit-cli` 是自动化插件的工具，不适用）。

| 方式 | 命令 | 说明 |
|---|---|---|
| 本地调试 | `npm run dev` | 本地 HTTPS 服务，地址填进飞书；需与飞书所在网络可达 |
| 正式使用 | 见下方 GitHub Pages | 公开静态托管，地址稳定，证书由平台提供 |

**GitHub Pages 部署（当前采用）**

- 仓库：[silasliu/lark-base-relation-viz](https://github.com/silasliu/lark-base-relation-viz)（public）
- 访问地址：<https://blog.silas.fun/lark-base-relation-viz/>
- 源码在 `main` 分支，构建产物在 `gh-pages` 分支，Pages 从 `gh-pages` 发布
- 更新流程：改代码 → `npm run build` → 把 `dist` 内容推到 `gh-pages`

> `public/mock-data.json` 是从真实 Base 导出的快照，只在本地调试用。
> `vite.config.ts` 里 `build.copyPublicDir: false` 保证它**不会**进入构建产物，
> 因此公开部署的版本不含任何真实数据。

## 为什么「唤起客户端」可能没反应

飞书把扩展跑在 **sandboxed iframe** 里。按 HTML 规范，沙箱 iframe 里指向自定义协议（`ticktick://`）的导航会被**静默丢弃**，除非宿主授予 `allow-popups` 或 `allow-top-navigation-to-custom-protocols` —— 这两个 token 由飞书控制，插件改不了。

所以：

- **网页版链接**（`https://dida365.com/webapp/#p/...`）永远可用，是主路径。
- **唤起客户端**用真实的 `<a href="ticktick://...">` 尝试（比 `a.click()` 信任等级更高），若被拦则无反应 —— 这不是插件 bug。
- 兜底：**「复制标题」**，粘进滴答搜索框即可。

`@lark-base-open/js-sdk` 没有任何打开外部协议或外部链接的 API（已核对 1.0.2 全部导出）。

## 关键实现说明

1. **节点尺寸必须传给 dagre**（`size: [w, h]`）。不传的话 dagre 按 40×40 排布，节点会大面积重叠——这是「标签互相覆盖」的真正原因，不是文字溢出。
2. **边的几何只由 `getPath` 决定**。G6 v4 在 item 更新时会用 `getPath` 重算路径，只在 `draw` 里写 path 会在重排后变形。
3. **控制点按布局主轴计算**：层级上下用垂直控制点，层级左右用水平控制点。混用会让斜边严重扭曲（实测偏离弦线 159px）。
4. **父子边必须 `return`**，否则会继续画第二条依赖边，叠加成「灰色虚线 + 红绿箭头」。
5. **用户没手动缩放过时，resize 会重新适配**；手动缩放过则保留视野。否则「首次适配发生在布局定型前」会留下被裁掉的图。
6. **适配必须防抖**。`整理` 会触发两次布局（清折叠 + 显式重排），两次都发 `afterlayout`；每次都立刻适配会停在中间帧，看起来就是「显示不全」。
7. **分页令牌必须保持数字**。`String(pageToken)` 会让超过 200 条的表在第二页直接失败。
8. **关系样式是注册表，不是分支**。颜色只留给状态；新增关系由 `relationStyles.ts` 分配线型，绘制代码不用改。
9. **节点 id 带表命名空间**（`tableId:recordId`）。单表时仍是纯 `recordId`，多表时不会互相覆盖。
10. **框选是自己实现的**。G6 的 `brush-select` 会在 `canvas:click` 时清掉自己的选择（它源码里的 TODO），
    所以框选改成捕获阶段监听 + `stopPropagation`，顺带也避免了同时平移画布。
11. **单选和框选用两个状态**（`selected` / `brush`）。共用一个状态会被任何一次 React 重渲染抹掉。

## 已知限制

1. 只读，不能在图上改关系。
2. 仅支持自关联字段；跨表关联不出现在下拉框。
3. 滴答跳转靠搜索（官方没有按 taskId 直达的 scheme），重名任务可能要多点一次。
4. 非 HTTPS 来源唤起滴答**每次都会弹确认**（见上文），无法在前端消除。
5. 父子字段只取第一个值。
6. G6 v4；`radial`/`circular` 布局的重叠由后置分离算法兜底，节点极多时可能有少量残余。
7. **多表共同显示还没开放**。数据模型已经准备好（命名空间节点 id、边上的 `relationId`、配置 v2），但界面仍是一次一张表。
8. **全屏指的是插件区域，不是整块屏幕**。刻意不用浏览器 Fullscreen API（它可能开新窗口/标签页，飞书 iframe 也可能拒绝），所以按钮只是把插件可用区域铺满。
9. **导出有尺寸上限**。最长边超过 4096px 会等比压缩；极大的图仍受浏览器 canvas 面积限制。
10. 读取是串行分页，正确但大表需要多次往返。
